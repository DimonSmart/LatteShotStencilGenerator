# IDD-0003.spec-svg-artwork-import-and-placement

## Intent

SVG artwork defines the opening cut through the uploaded stencil template. The
application accepts a safe fill-based SVG subset, normalizes it to planar
geometry, fits it into the configured artwork rectangle, and uses that exact
placement for preview and 3D cutting.

## Behavior

- Supported geometry includes svg, g, path, rect, circle, ellipse, polygon,
  closed polyline, viewBox, nested transforms, nonzero/evenodd fill rules, and
  common filled path commands including lines, Bézier curves, and arcs.
- Filled SVG regions become openings. Stroke-only artwork is not silently
  converted; the application explains that strokes must be converted to filled
  paths when needed.
- Scripts, external resources, external CSS, remote images, DTD/external
  entities, animations, and other active or network-backed SVG content are
  rejected or ignored safely.
- The artwork rectangle is derived from the current template top-view bounds and
  the user's left/right/top/bottom margins.
- On initial load, artwork uses aspect-ratio-preserving Contain placement and is
  centered in the available rectangle. The user can adjust scale and X/Y
  offsets and reset to fit.
- Placement controls are expressed in millimetres in the same top-view
  coordinate system as IDD-0002.
- The visual orientation of the source SVG is canonical. Viewed from the
  template's top side, the cut must match that orientation. The internal
  conversion between SVG's screen-style coordinates and 3D model coordinates
  must not produce an accidental mirror or rotation.
- The cutting solid extends beyond the template's full Z bounds so a requested
  artwork opening is a real through-hole wherever it intersects template
  material.
- Artwork that exceeds the configured working rectangle is reported and blocks
  export until corrected or refitted.
- Complexity limits for source elements, flattened curves, and file size are
  explicit. Exceeding a limit produces a clear error rather than a frozen tab.

## Product-Significant Architecture And Constraints

- SVG parsing and curve flattening produce project-owned planar geometry before
  stencil topology and solid boolean operations.
- Preview and export use the same normalized artwork placement.
- The application never fetches referenced artwork resources from the network.

## Non-goals

- Raster tracing, automatic stroke-to-outline conversion, and arbitrary SVG
  rendering fidelity are outside the initial scope.
- Perspective projection and wrapping onto non-planar template surfaces are
  outside scope.

## Acceptance Criteria

- Valid filled SVGs containing holes, nested contours, Bézier curves, and arcs
  fit into the working rectangle without distorted proportions.
- An asymmetric SVG produces the same top-side orientation in the preview and
  exported model.
- The final opening cuts fully through the template thickness.
- Unsupported or unsafe SVG content is explained rather than silently producing
  different geometry.

## Verification

- Maintain fixtures for simple shapes, rings, letters with counters, nested
  holes, evenodd/nonzero fill rules, transformed paths, curves, arcs, multiple
  islands, stroke-only input, unsafe external references, and asymmetric
  orientation.
