# IDD-0007.spec-mvp-operability-and-quality

## Intent

The browser application stays usable while parsing meshes and performing
potentially expensive geometry operations. Large or invalid input produces
progress and actionable limits rather than a frozen page.

## Behavior

- User-visible processing stages distinguish template import, SVG import,
  placement/topology, bridge generation, solid boolean generation, preview
  update, and export preparation.
- CPU-heavy geometry work runs away from the main UI event loop so orbiting the
  view, progress display, and cancellation/stale-result handling remain
  responsive.
- Rapid edits are debounced or coalesced. Older in-flight geometry results are
  discarded when newer design state exists.
- Template and SVG size/complexity limits are explicit and configurable.
  Exceeding a limit produces a clear error before uncontrolled memory or CPU
  growth.
- Invalid STL/3MF topology, unsupported SVG content, boolean failures, and
  export failures have distinct user-facing messages.
- Inputs are deterministic: identical template bytes, artwork, placement,
  bridge settings, caption settings, and colors produce geometrically
  equivalent output.
- The application does not require cross-origin APIs, a backend, or a service
  worker to perform its core generation workflow.
- Production builds are tested before GitHub Pages deployment.

## Product-Significant Architecture And Constraints

- The application must remain deployable as ordinary static files on GitHub
  Pages.
- Heavy work may use Web Workers and WebAssembly libraries, but must not require
  a server-side companion.
- Temporary geometry created for failed or superseded operations is releasable
  so repeated edits do not cause unbounded memory growth.

## Non-goals

- Instantaneous recomputation for arbitrarily large professional CAD meshes is
  not promised.
- Automatic repair of every malformed STL/3MF file is not required.

## Acceptance Criteria

- A typical coffee-stencil template and SVG can be edited without multi-second
  main-thread freezes.
- A complex but permitted operation shows progress and either completes,
  reports a specific error, or is safely superseded by a newer edit.
- Repeated edits do not apply out-of-order results.
- Invalid input never leaves controls permanently disabled.
- A production build works from the configured GitHub Pages project subpath.

## Verification

- Stress template import, SVG import, repeated placement changes, boolean
  generation, and both export paths.
- Verify stale worker results cannot overwrite newer state.
- Verify explicit failure cases for invalid meshes, unsafe SVG, complexity
  limits, boolean failure, and 3MF/STL serialization.
