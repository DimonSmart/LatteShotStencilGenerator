# IDD-0002.spec-template-and-reference-card

## Intent

The previous Donut card remains the reference coffee-stencil template and
provides useful default dimensions, placement zones, and regression geometry.
The new product is not limited to this shape: an uploaded 3D template is the
actual geometry source.

## Behavior

- Template-local UI coordinates use a top view. The origin is the upper-left
  corner of the template XY bounding box; X increases to the right and Y
  increases downward. This coordinate system is for placement controls and is
  mapped internally to the 3D coordinate system.
- The uploaded model orientation is preserved. The top side is the +Z-facing
  side after import normalization; the application does not silently rotate or
  mirror the model.
- STL contains no standard unit metadata, so STL coordinates are interpreted as
  millimetres. 3MF declared units are converted to millimetres.
- A template must contain usable printable solid geometry. Empty, non-finite, or
  geometry that cannot be treated as a watertight/manifold printable solid is
  rejected with an actionable message rather than passed into destructive
  boolean operations.
- The reference card bounding box is 88.345 mm wide by 113.882 mm high.
- The historical reference card has approximately 0.998 mm base thickness and a
  0.200 mm raised outer/header layer.
- Its default artwork rectangle starts at X=6.678 mm, Y=33.029 mm and measures
  74.989 by 74.989 mm. Expressed as bounds-relative margins, these values are
  left=6.678 mm, right=6.678 mm, top=33.029 mm, bottom=5.864 mm.
- Its default caption rectangle starts at X=6.678 mm, Y=0 and measures
  74.989 by 33.029 mm.
- For any uploaded template, the user can change the four artwork margins.
  Reference dimensions are defaults and examples, never a reason to replace the
  uploaded mesh with generated geometry.

## Product-Significant Architecture And Constraints

- The template mesh, not the reference dimensions, is the source of truth for
  the exported physical model.
- Model-space conversion must have one explicit orientation mapping shared by
  SVG placement, preview, caption placement, boolean cutting, and export.
- Any bundled reference template should be consumed through the same import path
  as a user-uploaded template so reference behavior does not become a separate
  geometry implementation.

## Non-goals

- Triangle-for-triangle reconstruction of the historical Donut STL is not
  required.
- Automatic best-fit reorientation of arbitrary models is outside initial scope.

## Acceptance Criteria

- The reference layout reproduces the 88.345 by 113.882 mm top-view bounds and
  74.989 by 74.989 mm artwork rectangle within 0.05 mm.
- Loading a different rectangular or round plate-like template changes the
  preview and export geometry without changing the core workflow.
- An asymmetric model and asymmetric SVG preserve their intended top-view
  handedness through import, preview, boolean cutting, and export.

## Verification

- Keep a reference-card regression covering bounding box, artwork margins,
  caption rectangle, and orientation.
- Add an asymmetric orientation fixture so an accidental X/Y flip, mirror, or
  180-degree rotation fails visibly.
