# ENG-0004.rule-browser-geometry-and-format-stack

## Rule

Use the following default browser stack unless a later engineering decision
documents a concrete replacement:

- Three.js for the interactive 3D viewport and standard browser-side STL/3MF/SVG
  format integration where its loaders/exporters meet the required contract.
- manifold-3d for robust 3D boolean/manifold operations and planar CrossSection
  operations.
- opentype.js for deterministic conversion of bundled font glyphs to outlines.
- A dedicated 3MF export adapter implementing the 3MF Core model plus required
  standard color/material properties. @jscadui/3mf-export with fflate is the
  preferred starting point, but the adapter contract takes precedence if color
  support requires a small standards-focused extension or replacement.

Run expensive Manifold work in a Web Worker. Use the normal single-threaded WASM
build rather than requiring SharedArrayBuffer or special cross-origin isolation
headers.

## Applicability

Always

## Rationale

Three.js already provides maintained STLLoader, ThreeMFLoader, SVGLoader, and
STLExporter integration and is a natural preview renderer. Manifold provides a
topology-focused WASM kernel suited to boolean editing of printable solids.
opentype.js supplies browser-side glyph outlines. 3MF needs explicit
color/material control and therefore remains behind its own adapter.

Keeping Manifold single-threaded inside a worker fits ordinary GitHub Pages
hosting while still moving expensive CSG off the UI thread.

## Guidance

- Bundle libraries with the application; do not depend on runtime CDN
  availability for core functionality.
- Keep exact dependency versions pinned by the package lock.
- Treat ThreeMFLoader support and 3MF exporter support as independent concerns.
- Validate generated 3MF in real slicers, not only by re-importing it through the
  same JavaScript code.
- Preserve millimetres explicitly at every file-format boundary.
- If a selected Three.js loader does not preserve a required 3MF feature, adapt
  or replace that format adapter without changing the geometry/domain model.

## Verification

The production build loads its bundled WASM on GitHub Pages, geometry work runs
outside the main UI thread, representative STL and 3MF templates import, SVG and
caption geometry reach the Manifold kernel through project-owned contracts, and
generated STL/3MF files open correctly in independent slicers.
